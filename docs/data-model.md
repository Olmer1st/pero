# Data model

Applies from turn 2. Schema source of truth: `core/migrations/` (sqlx, forward-only, embedded in the binary). This page explains the design; if they disagree, the migrations win.

## Where things live
| What | Where | Notes |
|---|---|---|
| Prose (books, chapters, scenes) | Markdown files in one Git repository per book | The only copy of the text. Every save is a Git commit. |
| Structure, identifiers, story graph, canon ledger | SQLite file (`pero.db`) | Never the only copy of prose. The structure tables can be rebuilt by re-reading the repositories; the story graph and canon ledger are authored data and are backed up with the database. |
| Server settings | `/etc/pero/server.toml` | Outside the repository. |

Planned layout on the server: `<data_dir>/pero.db` and `<data_dir>/books/<book-id>/` (the repository). `data_dir` is a config key added with the manuscript store.

## Identifiers
- Short random text IDs generated by the server (40 random bits, Crockford base32, lowercase), never reused, never derived from content or position.
- Books, chapters, scenes, entities, relationships, events and facts carry a type prefix (`bk_`, `ch_`, `sc_`, `en_`, `rl_`, `ev_`, `ft_`).
- Passage IDs are the bare 8-character value; the same value is the marker in the Markdown (see below).
- IDs are validated in the application, not by `CHECK` constraints, so the format can change without a table rebuild.
- Timestamps are UTC ISO 8601 text (`2026-10-28T09:10:00.000Z`).

## Passages (decided with the owner on 2026-10-28)
- **Granularity:** one paragraph (a block separated by a blank line). In Russian typography each dialogue line starting with «—» is its own paragraph and so its own passage. Headings and scene breaks are not passages.
- **Marker in Markdown:** a hidden comment at the end of the paragraph, `<!-- p:k7m2x9qa -->`. Invisible when rendered; it moves with the paragraph when text is edited or reordered. The API exposes passages as structured `{id, text}` items, so clients never edit markers by hand.
- **Edits:** changing the words keeps the ID. Splitting keeps the ID on the first part and gives the new part a new ID. Merging keeps the first ID and tombstones the other with `merged_into`. Moving a paragraph to another scene keeps the ID (`scene_id` changes).
- **Never deleted:** a removed or merged passage stays in `passages` as a tombstone (`status = 'removed'`, `removed_at`), so evidence links always resolve and the facts that cite it can be flagged instead of silently losing their evidence. A `DELETE` on a cited passage is refused by a foreign key.
- **Text hash:** SHA-256 (hex) of the normalised paragraph text (stored in `text_hash`); evidence stores the hash at the time of citing, so an edited passage marks its evidence out of date.
- **Normalisation** (import and save): line endings to `\n`, trailing spaces removed, one blank line between paragraphs, one final newline. Unicode is not changed: no NFC conversion, «ёлочки», dashes and «ё» are untouched.

## Tables

### Manuscript index (`0001_manuscript.sql`)
| Table | Purpose | Key columns |
|---|---|---|
| `books` | One per book | `title`, `language` (`ru`/`en`), `head_commit` (Git commit the index reflects) |
| `chapters` | Ordered chapters | `book_id`, `position`, `title`, `path` (repository-relative) |
| `scenes` | Ordered scenes in a chapter | `chapter_id`, `position`, `path`, `language`, front-matter copies `pov`, `story_date`, `location` |
| `passages` | Paragraph-level passages incl. tombstones | `scene_id`, `position`, `text_hash`, `status` (`active`/`removed`), `removed_at`, `merged_into` |

### Story graph (`0002_story_graph.sql`)
| Table | Purpose | Key columns |
|---|---|---|
| `entities` | Characters, places, organizations | `kind`, `name`, `description` |
| `entity_aliases` | Other names and forms (nicknames, inflected forms); the base of the name registry in the deterministic checks | `entity_id`, `alias` |
| `relationships` | Entity to entity, free-text kind | `from_entity_id`, `to_entity_id` (never equal), `kind`, `directed` |
| `timeline_events` | Events with the author's date text and manual order | `title`, `when_text`, `sort_order`, `scene_id`, `place_id` |
| `timeline_event_participants` | Who took part | `event_id`, `entity_id`, `role` |

### Canon ledger (`0003_canon_ledger.sql`)
| Table | Purpose | Key columns |
|---|---|---|
| `facts` | A statement about the story | `entity_id` (optional subject), `text`, `status`, `origin` (`author`/`ai`/`import`), `source_ref`, `stale`, `stale_reason`, `approved_by`, `approved_at` |
| `fact_evidence` | Supporting passages (one or more, enforced by the API) | `fact_id`, `passage_id`, `text_hash` at citing time |
| `fact_status_history` | Every status change | `fact_id`, `from_status`, `to_status`, `changed_by`, `reason`, `changed_at` |

Fact statuses: `explicit` (stated in the text), `author_approved`, `ai_hypothesis`, `rejected` (the author refused a hypothesis; added to the three in the handoff so a refusal has somewhere to go). Rules in the schema:
- `author_approved` requires `approved_by` and `approved_at`, written only by the explicit approve call, so an AI hypothesis cannot become canon by a plain update.
- `stale_reason` is allowed only when `stale = 1`.
- Evidence and history rows must point at existing facts and passages.

## Rules enforced by the database
Foreign keys are on for every connection (`PRAGMA foreign_keys`); nothing cascades, so removing a parent row with children is refused. Enumerations, lengths, hash length and the passage and fact rules above are `CHECK` constraints. Tables are `STRICT`. The file uses WAL journaling and a 5-second busy timeout.

## Migrations
- Files `core/migrations/NNNN_name.sql`, applied in version order at startup; applied versions and checksums are kept in `_sqlx_migrations`. Editing an applied migration is detected and refused; fix by adding a new one.
- Forward-only: there are no down migrations. Back up the database before a release that changes the schema.
- Tests (`db::tests`): apply to an empty database; apply twice (no change); roll forward over a database that already holds data; opening a file keeps data; invalid rows are rejected and their valid counterparts accepted; Cyrillic text round-trips byte for byte.
