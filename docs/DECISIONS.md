- 2026-10-28 — Turn 2 part 4: story graph CRUD lives in SQLite only (`graph.rs`, `graph_api.rs`), strict bodies, everything scoped to one book. An entity's kind and a relationship's two ends are immutable (delete and recreate). - 2026-10-28 — Turn 2 part 5: canon ledger in SQLite (`canon.rs`, `canon_api.rs`). The author's own facts start as `author_approved` (entering one is the explicit act) with evidence optional; AI facts can only start as `ai_hypothesis` and import facts as `explicit`, both with at least one cited passage; `approve` (ai_hypothesis or rejected to author_approved, records who and when) is the only route to canon for a fact that did not start approved, enforced in the API and by a database CHECK. `reject` works from any status, `reopen` only for AI-origin facts; each change writes a history row, which is what makes bulk approval reversible later. Facts are never deleted; they are rejected. Stale flags are set inside the manuscript index sync (same transaction as the passage tombstones) for removed, merged and edited cited passages and cleared only by re-citing; approval does not clear them. The actor is `api` until device authentication (part 6). — Meets "no AI guess becomes canon without approval" and "deleting a passage flags facts that cite it" without losing any record.
- 2026-10-28 — Turn 2 part 6: device authentication. A device token is 256 random bits (`pero_` + 64 hex), shown once, stored only as its SHA-256 hash (a fast hash is right for a random 256-bit secret; no lockout, since guessing is infeasible); checked against the database on every request so revocation is immediate. One middleware covers every `/api/v1` route and any path under it with an identical 401, and handlers take the acting device from it, so the device name replaces the placeholder actor in Git authorship and the canon ledger. `/health` stays unauthenticated (issue #12 decides). Devices are registered only through the server CLI (`pero-server device add|list|revoke`, refused as root so the database files stay owned by the service user), never through the API, so a stolen token cannot mint tokens; the API offers `me`, `devices` and `revoke` (any device may revoke any device). Devices are revoked, never deleted, and a revoked name is not reused, so history is never ambiguous. The API is still mounted only when `data_dir` is set; setting it is now safe. — Meets "requests without a valid token are rejected; revoking one device leaves others working".
